# Siri – Gesture classifier — Technical notes
Author: Siri   |   Files owned: `src/model/train.py`, `src/model/evaluate.py`, `src/model/predict.py`   |   Requirement IDs: CL.1–CL.4, R6, R11

## 1. What it does
This component acts as the "brain" of the simulation, taking the mathematical hand coordinates and predicting what gesture they represent.

`train.py` builds and tunes a Support Vector Machine (SVM) using Shobita’s dataset,
`evaluate.py` tests how accurate it is on unseen people, and
`predict.py` provides a fast classifier object that Evan’s game logic can call in real time.

In the pipeline ([DESIGN.md §2](../DESIGN.md#2-system-architecture)), this sits exactly between data preprocessing and the game state controller.

## 2. Design decisions
| Decision | Alternatives considered | Why we chose it |
|---|---|---|
| Use an SVM with RBF kernel | Neural Networks, Random Forests | SVMs are extremely fast for real-time inference (no lag) and perform exceptionally well on small, structured tabular data like 63-feature vectors. |
| Apply `StandardScaler` first | Train directly on raw data | SVMs are distance-based; scaling ensures all 63 coordinate features are weighted equally. |
| Use `LeaveOneGroupOut` (LOUO) | Standard k-fold cross-validation | Standard splitting would mix the same user's frames into both train and validation. LOUO ensures we tune the model based on how well it generalizes to entirely new people. |
| Use `joblib` for saving | `pickle` or custom JSON | `joblib` is heavily optimized for scikit-learn models and large NumPy arrays, making loading instantaneous when the game launches. |

## 3. Interfaces provided / consumed
**Provided:** 
- `predict(features: np.ndarray) -> str` (Used by Evan’s integration logic)
- Saved `models/classifier.pkl` (Loaded at game start)

**Consumed:**
- `load_dataset()` and `load_splits()` from Shobita’s data module
- 63-feature NumPy arrays generated by Triet’s `preprocess()` pipeline

## 4. Challenges and how we solved them
- **Challenge:** Preventing the model from memorizing individual hand quirks.
- **What we tried:** Grouping data by `user_id` and using `LeaveOneGroupOut` CV instead of standard random splits
- **What worked:** The model successfully generalized to new users, evidenced by an 85.44% test accuracy on the completely unseen holdout set.

## 5. Results
- **[Must] Tuning:** Best hyperparameters were `C=10` and `kernel: rbf`.
- **[Must] Validation:** Cross-Validation Accuracy was 86.7%.
- **[Must] Final Test:** Overall Test Accuracy on the held-out test set was **85.44%**.
- **[Nice] Confusion Matrix Analysis:**
  - V-sign (97% precision/recall) and Fist (88% precision) are the strongest.
  - The model gets confused most often distinguishing "none" (relaxed hand) from an "open palm". "None" had the lowest recall (51%), meaning the model often predicts a relaxed hand as an open palm.

## 6. Limitations & future work
- **The "None" Class:** Because "none" encompasses an infinite number of random hand poses, it is the hardest to classify. Future work should collect a much wider variety of "none" poses to improve recall.
- **Lighting Robustness:** We did not split the evaluation strictly between bright and dim conditions, so it is unclear if the 85.44% accuracy drops significantly in dim lighting alone.
- **Temporal Context:** The SVM looks at a single isolated frame. It cannot understand motion (like a wave), only static poses.

## 7. Slide summary
**Text:** We trained a Support Vector Machine (SVM) pipeline with standard scaling, using Leave-One-Group-Out cross-validation to prevent data leakage. The finalized RBF model achieved 86.7% CV accuracy and 85.44% test accuracy on unseen users, running fast enough for real-time game integration.
